Точные форматы запросов и ограничения приведены в CONTRACTS.md. Запросы и результаты передаются строками JSON в UTF-8: один входной и один выходной объект на строку, в том числе для последовательных запросов разных задач и размеров. ## 4. Часть 1: Связность с помощью DSU

Площадки фестиваля соединяются кабелями, которые добавляются по одному. После каждого добавления определите число компонент связности и размер наибольшей компоненты.

Реализуйте dsu на основе системы непересекающихся множеств со сжатием путей и объединением по размеру или рангу. Изначально каждая вершина образует отдельную компоненту. Повторное объединение и объединение вершины с самой собой не изменяют существующую компоненту. При сжатии пути сохраните возможность пройти к корню, изменяя parent. При объединении по рангу учитывайте размеры отдельно: ранг не равен размеру компоненты. Изначально largest=1 при n>0 и largest=0 при n=0.

**Вход:** n и operations — последовательность пар вершин. **Выход:** states — пары [components, largest] после каждой операции. При n=0 массивы operations и states пусты.

Пример: для n=4 и operations=[[0,1],[1,2],[0,2],[3,3]] результат states=[[3,2],[2,3],[2,3],[2,3]]. Последние две операции не объединяют компоненты.

**Требуемая сложность:** O(n+q α(n)) амортизированного времени и O(n+q) памяти. Инициализация занимает O(n), q операций — O(q α(n)) амортизированного времени. Более свободная оценка O((n+q) α(n)) также является корректной верхней границей.

## 5. Часть 2: Кабельная сеть минимальной стоимости

Для неориентированного взвешенного графа найдите минимальный остовный лес. В каждой компоненте выбранные рёбра должны соединять все вершины без циклов и иметь минимальную суммарную стоимость. Изолированные вершины также считаются компонентами.

Выполните две отдельные реализации: kruskal — с сортировкой рёбер и DSU; prim — со списками смежности и очередью с приоритетом. Прим должен начинать обработку с новой непосещённой вершины, пока не будут обработаны все компоненты.

**Вход:** n и edges, где ребро представлено как [u,v,weight]. **Выход:** cost, edge_ids и components. Каждый выбранный ID ребра встречается один раз. Параллельные рёбра и отрицательные веса допустимы; петли не включаются в лес. Принимается любой оптимальный лес. Если входной граф имеет c компонент связности, верните ровно n-c рёбер. 

Краскал принимает ребро только при `find(u) != find(v)`. По свойству разреза безопасно минимальное ребро, пересекающее разрез, который не пересекает рёбра текущего леса. При n=0 верните cost=0, edge_ids=[] и components=0.

Пример: n=4, edges=[[0,1,4],[1,2,2],[0,2,3]]. Рёбра с ID [1,2] дают cost=5 и components=2; вершина 3 изолирована. При нескольких оптимальных лесах Краскал и Прим могут вернуть разные допустимые ID рёбер.

**Требуемая сложность:** Краскал O(n+m log(m+1)); Прим O(n+m log(m+1)) с ленивой кучей или O((n+m) log(n+1)) с индексированной кучей. Память: O(n+m).

## 6. Часть 3: Компоненты сильной связности

В графе подготовки ребро u→v обозначает зависимость работы v от работы u. Найдите компоненты сильной связности (SCC): максимальные группы вершин, взаимно достижимых по направленным рёбрам.

Реализуйте scc методом Косарайю с двумя обходами DFS и транспонированным графом. Верните метку компоненты для каждой вершины и граф конденсации. Во втором проходе используйте убывающий порядок времени завершения первого прохода. Допустимы проходы сначала по G, затем по транспонированному графу, или наоборот, с соответствующим порядком завершения. Метки могут быть любыми неотрицательными целыми числами. Одинаковая метка должна обозначать ровно одну SCC.

**Вход:** n и ориентированные рёбра [u,v]. **Выход:** component и condensation. Рёбра конденсации задаются парами меток компонент. Каждая направленная пара разных компонент включается один раз; внутренние рёбра и повторяющиеся пары исключаются. Изолированные вершины образуют отдельные SCC. Повторяющиеся рёбра и петли допустимы. При n=0 оба массива пусты.

Пример: рёбра 0→1, 1→0, 1→2, 0→2, 2→3 допускают component=[5,5,7,9] и condensation=[[5,7],[7,9]]. Два ребра из первой SCC к вершине 2 дают одно ребро конденсации.

**Требуемая сложность:** O(n+m) ожидаемого времени при удалении повторных пар с помощью хеш-множества; O(n+m) памяти.

## 7. Часть 4: Порядок подготовительных работ

Для ориентированного графа зависимостей определите, можно ли составить расписание всех работ. Если можно, верните топологический порядок: каждая предварительная работа должна предшествовать зависимой от неё работе.

Реализуйте topo через DFS с тремя состояниями: непосещённая, активная и завершённая вершина. Ребро в активную вершину указывает на цикл; само по себе ребро в завершённую вершину не указывает на цикл. Для ациклического графа обратный порядок завершения DFS даёт требуемый результат.

**Вход:** n и ориентированные рёбра [u,v]. **Выход:** acyclic и order. При цикле в любой компоненте верните acyclic=false и order=[]. Иначе верните acyclic=true и допустимый порядок всех вершин без повторений, включая изолированные. При n=0 результат acyclic=true и order=[]. Петля является циклом.

Пример: рёбра 0→2, 1→2, 2→3 допускают order=[0,1,2,3] или [1,0,2,3].

**Требуемая сложность:** O(n+m) времени и памяти.

## 8. Часть 5: Кратчайшие маршруты доставки

Для ориентированного взвешенного графа и заданного источника найдите кратчайшие пути из источника с помощью обработки DAG в топологическом порядке. Отрицательные веса допустимы.

Реализуйте dag. Проверьте весь граф на наличие циклов, затем обработайте ациклический граф в топологическом порядке, релаксируя исходящие рёбра только из достижимых вершин. Цикл должен быть отклонён, даже если он недостижим из источника.

**Вход:** n, edges [u,v,weight] и source, где n≥1 и 0≤source<n. **Выход:** acyclic, distance и parent_edge. Для графа с циклом верните acyclic=false и два пустых массива. Для ациклического графа верните acyclic=true и расстояние и родительское ребро для каждой вершины. У источника distance=0 и parent_edge=-1; у недостижимой вершины distance=null и parent_edge=-1. Для остальных вершин parent_edge указывает на входящее ребро кратчайшего пути из источника. При равных стоимостях принимается любой кратчайший путь. Это относится и к оптимальным параллельным рёбрам с разными ID. Для недостижимого расстояния используйте null: -1 может быть корректным отрицательным расстоянием. ID ребра не является номером вершины-предшественника.

Пример: n=5, source=0, edges=[[0,1,3],[0,2,8],[1,2,-7],[2,3,4]]. Результат distance=[0,3,-4,0,null] и parent_edge=[-1,0,2,3,-1]. Маршрут к вершине 3: 0→1→2→3, суммарная стоимость 0.

Добавьте вспомогательную функцию восстановления последовательности вершин маршрута по parent_edge. Вызовите helper в собственных тестах для достижимой вершины, источника и недостижимой вершины и запишите результаты в анализе. Достижимый маршрут идёт от источника к цели; маршрут к источнику — [source]; документируйте результат «маршрута нет» для недостижимой цели. Следуйте конкретным ID parent_edge, в том числе для параллельных рёбер. Helper входит в вашу реализацию и не является отдельной задачей JSON. Параллельные рёбра допустимы; петля делает граф циклическим.

**Требуемая сложность:** O(n+m) времени и памяти; O(длины маршрута) времени и памяти результата для восстановления пути.
