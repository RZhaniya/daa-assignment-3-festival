Для фестиваля нужно соединить площадки, составить план подготовки и организовать доставку. Реализуйте набор алгоритмов для трёх моделей: неориентированные кабельные сети, ориентированные зависимости и ориентированные маршруты доставки.

## Цели и предварительные знания

Реализуйте и объясните DSU, Краскала, Прима, SCC Косарайю, топологическую сортировку через DFS и кратчайшие пути в DAG. Научитесь проверять восстановленные ответы, учитывать равные оптимумы и граничные случаи, восстанавливать маршруты и обосновывать сложность. Необходимы списки смежности, DFS, сортировка, очередь с приоритетом и 64-битная арифметика.

## Интерфейс программы

На каждую строку входа с одним JSON-объектом выведите одну строку с JSON-результатом. Один запрос содержит одну задачу. Не выводите приглашения и отладочные сообщения в stdout. Перед каждым запросом сбрасывайте состояние. Готовые адаптеры отвечают за ввод и вывод. Вход соответствует опубликованным ограничениям; некорректный JSON не оценивается. Кодировка — UTF-8, регистр имён задач важен.

Вершины и рёбра нумеруются с нуля. ID ребра — его позиция во входном массиве. Стоимости, расстояния, веса и счётчики должны поддерживать знаковые 64-битные целые числа. null обозначает недостижимую вершину.

## Задача 1. Связность — DSU

Соединяйте площадки по одной связи. После каждой операции верните число компонент и размер наибольшей.

Вход: {task:dsu,n,operations:[[u,v],...]}

Выход: {states:[[components,largest],...]}

Ограничения: 0 ≤ n ≤ 100000; 0 ≤ q ≤ 250000 операций. При n=0 операций нет. Повторное объединение и объединение вершины с собой допустимы.

Реализуйте find и union со сжатием путей и объединением по размеру или рангу. Изначально есть n одноэлементных компонент; при n=0 largest=0. Записывайте состояние после каждой операции. Объединение внутри одной компоненты ничего не меняет.

Сложность: O((n+q) alpha(n)) амортизированного времени; O(n+q) памяти с учётом результата.

Пример входа:

```json
{"task":"dsu","n":4,"operations":[[0,1],[1,2],[0,2],[3,3]]}
```

Допустимый результат:

```json
{"states":[[3,2],[2,3],[2,3],[2,3]]}
```

## Задача 2. Кабельная сеть — Краскал

Постройте минимальный остовный лес неориентированного взвешенного графа.

Вход: {task:kruskal,n,edges:[[u,v,weight],...]}

Выход: {cost,edge_ids:[...],components}

Ограничения: 0 ≤ n ≤ 100000; 0 ≤ m ≤ 250000; −1000000000 ≤ weight ≤ 1000000000. Петли и параллельные рёбра допустимы.

Реализуйте Краскала с DSU. Учитывайте все компоненты, включая изолированные вершины; при n=0 components=0. cost — сумма весов леса. edge_ids содержит ID исходных рёбер без повторений. Петли не включаются. Принимается любой оптимальный лес. Отрицательные веса допустимы.

Сложность: O(n+m log(m+1)) времени; O(n+m) памяти.

Пример входа:

```json
{"task":"kruskal","n":4,"edges":[[0,1,4],[1,2,2],[0,2,3]]}
```

Допустимый результат:

```json
{"cost":5,"edge_ids":[1,2],"components":2}
```

Вершина 3 изолирована: лес стоит 5 и не соединяет все площадки в одну компоненту.

## Задача 2. Кабельная сеть — Прим

Независимо реализуйте построение того же минимального остовного леса, расширяя по одной компоненте.

Вход: {task:prim,n,edges:[[u,v,weight],...]}

Выход: {cost,edge_ids:[...],components}

Ограничения и требования к лесу совпадают с задачей Краскала. Используйте списки смежности и очередь с приоритетом. Начинайте заново в каждой ещё не посещённой компоненте. Стоимости должны совпадать с Краскалом; наборы ID могут отличаться. Сравните реализации на трёх размерах входа в ANALYSIS.md.

Сложность: O(n+m log(m+1)) с ленивой кучей; O((n+m) log(n+1)) с индексированной кучей; O(n+m) памяти.

Пример входа:

```json
{"task":"prim","n":3,"edges":[[0,1,1],[1,2,1],[0,2,1]]}
```

Допустимый результат:

```json
{"cost":2,"edge_ids":[0,2],"components":1}
```

Оптимальных ответов несколько: проверяется корректность леса, а не совпадение с одним списком рёбер.

## Задача 3. Циклические зависимости — SCC

Найдите компоненты сильной связности ориентированного графа и постройте конденсацию.

Вход: {task:scc,n,edges:[[u,v],...]}

Выход: {component:[метка каждой вершины],condensation:[[from_label,to_label],...]}

Ограничения: 0 ≤ n ≤ 100000; 0 ≤ m ≤ 250000. Повторяющиеся рёбра и петли допустимы.

Реализуйте Косарайю: два прохода DFS и транспонированный граф. Метки — неотрицательные целые числа; значения и порядок произвольны. Одинаковая метка должна означать ровно одну SCC. Конденсация содержит каждую пару различных компонент, связанную исходным ребром, ровно один раз и не содержит внутренних рёбер. Учтите изолированные вершины и глубокие графы. При n=0 оба массива пусты. Конденсация является DAG, но циклы внутри SCC остаются проблемой исходного расписания.

Сложность: O(n+m) ожидаемого времени при устранении повторов хеш-множеством; O(n+m) памяти.

Пример входа:

```json
{"task":"scc","n":4,"edges":[[0,1],[1,0],[1,2],[0,2],[2,3]]}
```

Допустимый результат:

```json
{"component":[5,5,7,9],"condensation":[[5,7],[7,9]]}
```

Вершины 0 и 1 принадлежат одной SCC; две связи между компонентами превращаются в одну.

## Задача 4. План подготовки — топологический порядок

Вход: {task:topo,n,edges:[[u,v],...]}

Выход: {acyclic:boolean,order:[...]}

Ограничения совпадают с ориентированным графом в SCC. Ребро u→v означает, что u должна завершиться до начала v.

Используйте DFS с состояниями «не посещена / активна / завершена» и обратным порядком завершения. Ребро к активной вершине означает цикл. При цикле в любой части графа верните acyclic=false и order=[]. Для DAG перечислите каждую вершину ровно один раз с соблюдением всех рёбер. Принимается любой допустимый порядок. Пустой граф: acyclic=true, order=[].

Сложность: O(n+m) времени и памяти, включая явный стек DFS.

Пример входа:

```json
{"task":"topo","n":4,"edges":[[0,2],[1,2],[2,3]]}
```

Допустимый результат:

```json
{"acyclic":true,"order":[1,0,2,3]}
```

Вершины 0 и 1 можно переставить; обе должны предшествовать 2.

## Задача 5. Доставка — кратчайшие пути в DAG

Вход: {task:dag,n,edges:[[u,v,weight],...],source}

Выход: {acyclic:boolean,distance:[целое число или null для каждой вершины],parent_edge:[ID ребра или −1 для каждой вершины]}

Ограничения: 1 ≤ n ≤ 100000; 0 ≤ m ≤ 250000; −1000000000 ≤ weight ≤ 1000000000; 0 ≤ source < n. Граф ориентированный; параллельные рёбра и петли допустимы на входе, но циклический граф нужно отклонить.

Проверьте ацикличность всего графа, затем релаксируйте рёбра в топологическом порядке. При любом цикле, даже недостижимом из source, верните acyclic=false и два пустых массива. Иначе у источника distance=0 и parent_edge=−1; у недостижимых вершин distance=null и parent_edge=−1. Для каждой другой вершины родительское ребро должно заканчиваться в ней и восстанавливать оптимальный путь из источника. Напишите вспомогательную функцию восстановления маршрута и покажите пример её использования. Не релаксируйте из бесконечности. Любой кратчайший маршрут допустим; остовное дерево решает другую задачу.

Сложность: O(n+m) времени и памяти. Восстановление пути — O(длины пути).

Пример входа:

```json
{"task":"dag","n":5,"source":0,"edges":[[0,1,3],[0,2,8],[1,2,-7],[2,3,4]]}
```

Допустимый результат:

```json
{"acyclic":true,"distance":[0,3,-4,0,null],"parent_edge":[-1,0,2,3,-1]}
```

Маршрут к 3: 0→1→2→3, стоимость 0. Вершина 4 недостижима. Отрицательные веса в DAG допустимы.
